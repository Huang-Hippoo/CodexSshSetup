# Codex SSH Setup v0.2.1

适用于固定 IP、每次启动可能更换 SSH 端口和后端节点的环境。

## 使用方法

1. 从 [v0.2.1 Release](https://github.com/Huang-Hippoo/CodexSshSetup/releases/tag/v0.2.1) 下载程序，关闭旧版后运行 `CodexSshSetup-v0.2.1.exe`。
2. 原有节点会自动读取，不需要重新添加。保持原来的节点名称。
3. 服务器重开后，从平台查看新端口。如果旧连接仍在重试，先断开该节点。
4. 修改 SSH 端口，然后点击日常连接。程序会保存新端口、同步 SSH 配置，并验证当前服务器身份。
5. 以前信任过的节点会自动识别。如果新节点没有你的公钥，会打开系统 SSH 窗口，请在该窗口输入服务器密码。程序不保存密码。
6. 如果出现“确认新的服务器身份”，通过平台控制台或管理员核对弹窗中的 SHA256 指纹后选择“是”；无法核对请选择“否”。

服务器端核对 ECDSA 指纹可执行：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub
```

弹窗如果显示其他算法，使用相应的 `ssh_host_ed25519_key.pub` 或 `ssh_host_rsa_key.pub`。

## 修复内容

- 保存端口时同步更新 SSH 配置，避免界面端口与实际 SSH 端口不一致。
- 服务器身份以固定 IP 对应的身份名称识别，不再以易变的端口作为唯一身份。
- 自动迁移本机 `known_hosts` 中同一 IP 各历史端口的明文可信密钥，并保存可信节点集合。多个历史节点可重复识别。
- 连接前从当前端口读取服务器密钥，仅使用历史可信密钥或用户明确核对批准的密钥，生成当前节点专用的校验文件。
- 保留严格的服务器身份验证。读取密钥本身不等于信任；未知身份必须由用户确认。
- 免密认证失败时自动进入公钥安装流程。交互式安装失败的 SSH 错误会写入日志，避免只显示“255／未知错误”。

可信节点集合：`%USERPROFILE%\.ssh\codex_ssh_setup_trusted_hosts`。
当前节点校验文件：对应专用私钥路径加 `.known_hosts`，文件中只有服务器公钥。
原始 `known_hosts` 保留。SSH 配置修改前继续生成原有备份文件。

该方案在同一固定 IP 的历史节点之间复用已有信任。如果 IP 日后被分配给完全不同的平台，应重新审查该 IP 的可信节点集合。

## 限制

- 新端口仍需从平台获取并填写；固定 IP 本身不能可靠推导属于你的实例的新端口。本版本不扫描其他用户的端口。
- 未知服务器身份仍需核对一次，之后同一节点换端口可自动识别。
- 如果平台每次都生成全新主机密钥，仍会要求核对。完全自动且可验证的长期方案需要平台提供主机证书、稳定 SSH 网关或经过认证的实例接口。
- 实例被删除、重建导致 Codex 登录凭据丢失时，仍需要重新登录。
- 原始 `known_hosts` 中的散列地址不会自动迁移；必要时会请求一次身份确认。
